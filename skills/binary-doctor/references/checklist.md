# 保存バイナリの不具合 観点集

差分の形から原因候補を引くための表です。候補は仮説であり、書き込みコードか再現で裏付けて初めて原因と言えます。

## 差分の形から引く

| 観測 | 疑う原因 | 裏付けの取り方 |
|---|---|---|
| ある位置から後がすべてずれる | フィールドの追加・削除、版数違いの構造体、可変長要素の長さ誤り | ずれの発生点のフィールドを特定し、書き出しと読み込みの定義を比べる |
| 4/8 バイト単位のずれが構造体の途中で出る | `#pragma pack` の違い、32/64bit の違い、`long`・`size_t`・`time_t`・ポインタのサイズ差 | `sizeof` とオフセットをビルド構成ごとに確認する |
| 末尾だけ途切れる | flush/close 漏れ、書き込み中の異常終了、ディスク容量不足、件数の誤り | 途切れ位置がバッファ境界か確認し、書き込みの戻り値処理を見る |
| 512/4096/65536 の倍数で途切れる | バッファ単位の書き込みで最後の flush が行われていない | close 前の経路、例外時の経路を見る |
| `0A` の前に `0D` が増える | テキストモードで開いている（`fopen` の `"w"`、`ios::binary` なし） | open のモード指定を見る |
| 2/4/8 バイトのバイト順が逆 | エンディアン変換の漏れ・二重変換 | 書き手と読み手のプラットフォーム、`htonl` などの有無を見る |
| 1 件ぶん欠ける、余る | ループ境界の off-by-one、件数の更新タイミング | 件数フィールドと実レコード数を比べる |
| レコードの順序が違う | 順序未定義のコンテナの列挙、ソート漏れ | 列挙元のコンテナを見る |

## 値から引く

| 観測 | 疑う原因 |
|---|---|
| `CC` / `CD` / `DD` / `FEEEFEEE` / `BAADF00D` | 未初期化領域（スタック・ヒープ）、解放後アクセス。MSVC のデバッグビルドで出るパターン |
| padding が非ゼロ | 構造体を未初期化のまま `fwrite`/`memcpy`。通常は無害だが、比較やチェックサムが不安定になる |
| 文字列の NUL の後に別の文字列の断片 | バッファの再利用でクリアしていない、前回値の残留 |
| 文字列に NUL 終端がない | `strncpy` の境界、固定長バッファのあふれ |
| 文字化け | SJIS/UTF-8/UTF-16 の取り違え。保存時と読込時の変換を比べる |
| ポインタらしい値 (`0x00007ff...`) | ポインタをそのまま保存。別プロセスでの読込で無効になる |
| NaN/Inf、極端に大きい浮動小数 | 未初期化、ゼロ除算、整数を浮動小数として解釈 |
| enum の範囲外、bool が 0/1 以外 | 未初期化、メモリ破壊、定義の版数違い |
| `0xFFFFFFFF` / `-1` | エラー戻り値をそのまま保存、未設定の番兵値 |
| 値が 0 に落ちている | 初期化順序の問題、読み込み前に保存している、条件分岐で設定が飛んでいる |
| 上限ちょうどで頭打ち、急に負になる | 整数の丸め・オーバーフロー、狭い型へのキャスト |

## 整合性

- 長さ・件数フィールドと実データは合っているか
- チェックサムは、正常ファイルで成立し不正ファイルで不成立か。**内容を変えた後の再計算漏れ**が典型
- ファイル中のオフセットが範囲内か、アラインメントは揃っているか
- ヘッダの版数と、実際のレイアウトが対応しているか

## 手順や状況から疑う

- 保存が途中で割り込まれていないか（別スレッドの更新、書き込み中の変更）。**一時ファイルを経由しない直接上書き**は、異常終了で壊れる
- 同時に複数のプロセスやスレッドが同じファイルに書いていないか
- 旧版のファイルを新版が読んでいないか（マイグレーション漏れ）
- 不具合が保存時に起きたのか、読み込み時に起きたのか。ファイルが正常なら原因はファイルの外（読み込み側）にある
