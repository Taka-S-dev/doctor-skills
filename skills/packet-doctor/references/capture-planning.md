# 取得計画（pcapがないとき）

症状と構成を聞き、**何を、どこで、どれだけ**取るかを具体的なコマンドで示す。取得してよいかは利用者が判断する。既存の資料でわかることは聞き直さない。

## 最初に確認すること

- 接続元と接続先のIP・ポート、間に入る機器（FW、NAT、VPN、スイッチ）
- いつ起きるか。再現できるか、頻度はどれくらいか
- どの機器でソフトを動かせるか。動かせない機器はミラーポートが使えるか

## どこで取るか

| 状況 | 取得位置 |
|---|---|
| まず全体を見たい | 問題を感じている側（接続元） |
| 応答がない、途中で消える | 接続元と接続先の**両方**を同時に。`two-point` で突合する |
| ソフトを動かせない機器 | スイッチのミラーポート（SPAN）。またはタップ |
| サーバーの処理遅延を測りたい | サーバーのすぐ近く |

ミラーは送受信の両方向を設定する。片方向だけだと `one_way_capture` になり「応答なし」を判断できない。

## コマンド

Windows（Wireshark導入済み、管理者権限が必要な場合あり）:

```powershell
& "C:\Program Files\Wireshark\dumpcap.exe" -D
& "C:\Program Files\Wireshark\dumpcap.exe" -i <番号> -f "host <相手IP>" -a duration:300 -w issue.pcapng
```

Linux:

```sh
sudo tcpdump -i <IF> -s 0 -w issue.pcap host <相手IP>
```

長時間（循環保存）。発生後すぐに止めないと該当部分が上書きされる:

```powershell
& "C:\Program Files\Wireshark\dumpcap.exe" -i <番号> -f "host <相手IP>" -b filesize:51200 -b files:20 -w ring.pcapng
```

`live` は、有限時間の取得と解析を同時に行う。実行前に対象インターフェースと取得の意図を利用者に確認する。

## フィルターの注意

- `tcp port 5000` だけにすると ICMP（FW拒否の通知）と ARP、DNS が見えない。迷ったらホストだけで絞る。
- FTPの制御ポートだけだとデータ接続が見えない。
- `-s` で切り詰めるとTLS証明書やアプリの判定は欠ける。TCPの解析はできる。

## 両端で取るとき

- できるだけ時計を同期する（`two-point` はずれを推定するが、推定には不確かさがある）。
- 症状が出る前に両方を開始し、症状が出た後に両方を止める。
- 操作した時刻を控えてもらう。解析の `--when` に渡す。

## 取得データの扱い

pcapには認証情報や機密データが含まれることがある。第三者に渡す前に利用者に確認する。外部へ共有するのは `export --anonymize` の要約を基本にする。匿名化は症状の文面までは保証しない。
